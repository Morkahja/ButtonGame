# AI development rules — Button Game

1. The human creator owns creative direction. Never attribute original concepts to AI or treat suggestions as approved decisions.
2. Preserve the established gameplay and Android-hosted Wi-Fi model unless the creator authorizes a change.
3. Before changes, inspect source, tests, workflows, and current documentation; never infer implementation from a task list.
4. Distinguish proposed, implemented, automated-test-passed, and device-verified states.
5. Use reviewable changes and tests. Do not alter signing identity or expose keystores, passwords, tokens, or private player data.
6. Update README.md, ROADMAP.md, CHANGELOG.md, and relevant docs with substantial implementation changes.
7. Record creator requests, AI proposals, corrections, decisions, implementation references, and verification in docs/DEVLOG.md.
8. Keep rejected or deferred ideas visible in docs/DECISIONS.md, not silently implemented.
9. Portfolio integration must preserve the game's independence and the creative record.
